# architecture-docs

Central repository for Architecture Decision Records (ADRs) and Solution Designs
across all teams. One place to find "what did we decide, and why."

Managed with [jerry](https://github.com/codcod/jerry): every rule in this
repository is enforced by the `jerry` binary, not by scripts committed here.

```sh
brew install codcod/tap/jerry     # or: go install github.com/codcod/jerry/cmd/jerry@latest
jerry validate
jerry index --check
```

## When to read this (and who has to)

A doc repo with no reading trigger becomes write-only. These are the triggers:

- **Before writing a solution design**, search for prior decisions in the same
  area. If one contradicts your design, supersede it explicitly.
- **During design review**, a reviewer checks whether the design conflicts with
  an `Accepted` ADR.
- **When onboarding onto a system**, read that team's `Accepted` ADRs first.
- **Quarterly**, the architecture guild sweeps `Proposed` ADRs older than 90
  days (`jerry validate` warns about these) and stale Solution Designs.

If a decision is never going to be looked up under one of these triggers, it
probably doesn't need an ADR.

## Structure

```
architecture-docs/
├── templates/               # ADR and Solution Design templates
├── index/index.md           # generated by `jerry index`
├── jerry.yaml               # rule configuration
├── teams/
│   └── <team-name>/
│       ├── adr/
│       └── solution-designs/
└── cross-cutting/           # decisions spanning multiple teams
    ├── adr/
    └── solution-designs/
```

There is deliberately no `scripts/` directory. The binary owns every rule, so
the rules cannot drift between repositories that share them.

## Adding a new team

```sh
jerry new adr "Your decision" --team <team-name>
```

The folders are created on demand. **Add a CODEOWNERS line for the team** —
without it your docs fall back to the catch-all reviewer rather than your team.

## Numbering and references

ADR IDs are **scoped per folder**: `ADR-0001`, `ADR-0002`, ... within
`teams/<team>/adr/`, and separately within `cross-cutting/adr/`. `jerry new`
allocates the next free number; `jerry validate` rejects duplicates.

Because IDs are only unique per folder, references to another folder must be
scope-qualified:

| Reference                | Means                              |
|--------------------------|------------------------------------|
| `ADR-0007`               | ADR-0007 in the same folder        |
| `payments/ADR-0007`      | ADR-0007 in `teams/payments/adr/`  |
| `cross-cutting/ADR-0003` | ADR-0003 in `cross-cutting/adr/`   |

Every `superseded_by`, `supersedes` and `related_adrs` reference is checked.

## Status lifecycle

**ADRs:** `Proposed` → `Accepted` | `Rejected`, and later `Deprecated` or
`Superseded`.

- `Rejected` is a first-class outcome — recording what you turned down is what
  stops the same proposal coming back every year.
- Never delete or rewrite an ADR. Use `jerry supersede`, which sets
  `status: Superseded` plus `superseded_by:` on the old one and writes the
  reverse pointer on the new one, so neither side can be forgotten.

**Solution Designs** perish: `Draft` → `In Review` → `Approved` →
`Implemented`, then `Archived` (or `Superseded`). An `Approved` design that was
never implemented is the most misleading artifact this repo can hold.

## Known trade-offs of this layout

Written down so they're a decision, not an accident:

- **Central repo, not per-service `docs/adr/`.** Optimizes lookup over
  proximity. The cost is drift: docs here are not touched by the merge requests
  that change the code they describe.
- **`teams/` as the primary axis.** Teams reorganize and decisions don't, so a
  reorg means moving files or living with a stale path.
- **Per-folder ID numbering.** Buys short IDs, costs scope-qualified references.
- **`cross-cutting/` needs more reviewers than a team folder**, which creates an
  incentive to file a multi-team decision under one team. Reviewers push back on
  this; `jerry validate` enforces that cross-cutting ADRs name two or more teams
  but cannot detect a multi-team decision hiding in a team folder.

See `CONTRIBUTING.md` for the process, and `templates/` for the files to copy.
